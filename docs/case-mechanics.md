# 六个委托，六种玩法

更新：2026-10-17。目标：六个委托**手上的动作各不相同**，但仍是同一家侦探事务所的委托——外壳一致、证据系统一致、学到的东西不重复。

现在的三关（小林、朵朵、小雨）走的是同一套：进房间 → 走动调查 → 搜源码 → 拼推理板 → 沙盒实验 → 对质。第二关开始就能猜到下一步，玩到第三关会腻。这份文档把「核心玩法」拆成六种，每关换一个手上的动作。

## 一、哪些不变（系列的身份）

- 像素小镇 → 委托人房间 → 走动调查：跟着人物走到东西前面按 E，这是比特镇的样子，不改。
- **侦探手账**：线索一律自动记进去，任何玩法都往里写。
- **结案对质**：最后拿证据反驳对方的说法，这是侦探的收尾，六关共用。
- **三档难度、自动存档、试玩徽章**：共用。
- 数据仍然全部写成 JSON，界面另写，正式版搬 Godot 时只换皮。

## 二、哪些变（每关的核心动作）

| # | 委托 | 手上的动作 | 参考游戏 | 一句话玩法 | 学的概念 |
|---|---|---|---|---|---|
| 1 | 小林 · 小账本 | **逐条判定、盖章** | Papers, Please · 奥伯拉丁的回归 | 把「隐私说明的每条承诺」和「程序实际行为」对上，盖「说到了 / 没说 / 说反了」 | 条款与真实行为的差距 |
| 2 | 阿哲 · 天气小助手 | **在长文本里找东西** | Hidden Folks · 找茬 | 在一卷压缩过的源码里找出四把真钥匙，排除示例值和同名变量 | 密钥硬编码 |
| 3 | 小雨 · 像素计算器 | **输入序列** | FEZ · Tunic（输入码） | 从练习册残页推出按键序列，亲手按出来才响 | 彩蛋与后门的界线 |
| 4 | 朵朵 · 种田存档 | **改数值、算校验** | Zachtronics · Opus Magnum | 改金币之后让校验和对上，算错就读成新农夫 | 数据格式与校验和 |
| 5 | 周姐 · 便签 1.1 | **双栏对比、找不同** | Her Story · 补丁对比 | 把 1.0 和 1.1 拉开看，找出被偷偷加上的行为 | 更新说明与真实改动 |
| 6 | 王奶奶 · 小光手电筒 | **布置权限、预演后果** | Baba Is You · Into the Breach | 在「灯还得亮」的前提下，让数据走不到广告服务器 | 最小权限 |

一句话概括手感差异：**盖章、找、按、算、比、布**。六个动词互不重叠，玩家每次坐下都要换一种手。

## 三、每关详设

### 1. 小林 · 隐私体检：核对台

- **界面**：一张木桌。左边一叠「隐私说明卡」（一条一张），右边「行为记录」（源码片段或日志），中间三枚木章。
- **循环**：抽一张说明卡 → 读两边的材料 → 盖一枚章。章盖下去不能改（Papers, Please 的规矩），盖错只是拿不到星，不卡关。
- **撒谎的方式**：有的条款写「我们不会读取剪贴板」，而代码里有 `readText`（说反了）；有的写「为了同步，可能需要设备信息」，含糊其辞（没说清）；有的老实写了（说到做到）。三种章都要有。
- **难度**：简单＝6 条、矛盾摆在明面；普通＝10 条，含 2 条只差一个词的；困难＝12 条，外加 30 秒一次的「小林催你」，没盖的算「没查」。
- **现有内容**：`board` 的三个分组正好当桌上的三个托盘，`terms` 直接当卡片上的高亮词。
- **为什么不是现在的推理板**：推理板是「把词填进句子」，核对台是「给一段承诺定性」，判定的对象不一样，手上的动作也不一样。

### 2. 阿哲 · 密钥自查：放大镜

- **界面**：一卷可以上下滚的代码纸，右边一个「扫描仪」，扫一次亮一批可疑片段。
- **循环**：扫描 → 逐个判定「真钥匙 / 假钥匙 / 只是名字」→ 全部标对才能点「发布」。
- **干扰**：必须有假目标，不然就是无脑点。四类假钥匙：示例值（`YOUR_API_KEY_HERE`）、测试用的公开 key、长得像 key 的变量名（`apiKeyName`）、base64 图片的开头。
- **难度**：简单＝扫描直接把可疑串高亮；普通＝只给「这几百行里有 4 把」；困难＝扫描有冷却，扫错区域会亮出无关内容，还会占用信任度。
- **现有内容**：关卡已补上（2026-10-17）。房间、六件调查物、四把钥匙、三个推理句和四句对质都在；**密钥自查实验室已经可用**——五个文件摊开，「扫一遍」把像密钥的字符串点亮，玩家挑出真能用的，挑到网址、版本号、输入提示这类假目标会记一次犯错。四把真钥匙全挑出来才算查完。
- **还没做**：独立成一个大玩法的「放大镜长卷」（可缩放、有冷却、困难档只给行号）——现在是终端里的实验室版本，教学效果已经到位。

### 3. 小雨 · 彩蛋：输入序列

- **界面**：手里一台像素计算器，屏幕上是一排圆点，按对一下亮一个。
- **循环**：读练习册残页 → 推理出按键顺序 → 在键盘上按 → 按对出祝福，按错清空。
- **彩蛋还是后门**：序列按出来以后不是结束——要用手账里的证据选一个结论：「这是彩蛋」还是「这是后门」，选错对质会吃亏。这是这一关真正的教学点。
- **难度**：简单＝残页给全 10 个键；普通＝缺最后两个；困难＝残页是被人改过的错码，得回去读源码里的 `SECRET_KEYS`。
- **现有内容**：`board` 的三组（祝福怎么来 / 开发工具藏在哪 / 专业版开关）刚好是推序列的三条线索。
- **手机**：横屏时屏幕下半是计算器键盘，按屏幕键和按键盘都算。

### 4. 朵朵 · 存档：改数值 + 算校验

- **界面**：左边存档字段表（名字 / 天数 / 金币 / 校验和），右边一张纸算校验，下面是「写回副本」。
- **循环**：改金币 → 按规则重算 `sum` → 写回 → 读档看结果。校验不对 → 读成新农夫，重来（副本还在，代价是回到上一步）。
- **难度**：简单＝公式直接写在便签上；普通＝要从两份合法存档反推 `SAVE_SALT`；困难＝还要同时改天数，且不能破坏另一处冗余字段。
- **现有内容**：`encodeSave` / `checksum` / `SAVE_SALT` 已经在样本代码里，直接变成练习题。
- **为什么耐玩**：这是唯一一关「改完之后能立刻看到世界变化」的，改对了农场里的金币真的变。

### 5. 周姐 · 版本对比：双栏找不同

- **界面**：左右两版文件树，中间一条可以拖的对比条；更新说明只有一行字钉在顶上。
- **循环**：先读那句「修复了一些小问题」→ 在两版之间找出三处真正影响用户的变化（每 10 分钟截屏上传、去掉了导出、申请了新权限）→ 挑够三处才能写结论。
- **陷阱**：四十处无关改动（重命名、缩进、注释、依赖升级版本号）混在里面，挑错会冤枉好人，扣信任度。
- **难度**：简单＝改动直接高亮、无关改动折叠；普通＝只列改动的文件；困难＝不给高亮，只给行数统计。
- **现有内容**：这一关也**没有关卡数据**，要写两版「样本程序」和它们的 diff。

### 6. 王奶奶 · 权限：数据流迷宫

- **界面**：一台手机的剖面图（客厅、相册、通讯录、定位、网络出口），每个权限是一道门。
- **循环**：开关六道门 → 按「预演」看数据往哪流 → 要求：手电筒还能亮（闪光灯门必须开），但通讯录、定位的数据不能走到广告服务器。
- **参考手感**：Baba Is You 的「改规则」，加 Into the Breach 的「先看后果再确认」——预演不消耗次数，但改的时候要想清楚。
- **难度**：简单＝三道门；普通＝六道门，其中两道是「开了也白开」的诱饵；困难＝系统会「自启动」偷偷补权限，要额外关掉自启，还会出现「合理用途」的解释来动摇你。
- **现有内容**：这一关**没有关卡数据**，要写房间、权限表、数据流和结论。

## 四、工程上怎么落

### 数据
`game.puzzle` 里新增一段，和现有字段并列，不破坏旧关卡：

```json
"mechanic": {
  "kind": "audit | scan | sequence | savefile | diff | permissions",
  "…": "每种玩法自己的字段，见下"
}
```

现有关卡没有 `mechanic` 时，仍然走现在的「搜索 + 推理板 + 沙盒」，不会立刻全废。

### 代码
- 每个玩法一个模块：`public/case-mini-<kind>.js`，导出 `create({ h, data, ui })`，返回 `{ open, close, solved }`。
- `case-session.js` 的 phase 机在 `investigate` 和 `confront` 之间插一步：有 `mechanic` 就开专属玩法，出结果再进对质；没有就沿用旧流程。
- 专属玩法只做「手感」，证据、手账、对质、存档、难度仍然由 `case-session` 统一管——这样六个玩法不会各自造一套存档。
- 键盘必须能玩完整关（不能只有鼠标），手机横屏可用，遵守「减少动态效果」。

### 测试
每个玩法把判定逻辑抽成纯函数（不碰 DOM），在 `test/` 里单测；再加一项「关卡可解」的数据检查（比如序列关的答案必须能从提示推出来）。

## 五、先做哪两个

1. **小雨 · 输入序列**（最小、见效最快）：能验证「专属玩法 + 共用外壳」这套接法，手机上按键盘也自然。
2. **朵朵 · 存档编辑器**（最完整）：数据模型已经有了，三档难度都能做出区别，改对了能立刻看到金币变化。

之后按 1 → 4 → 2 → 6 → 5 的顺序做，因为 2 / 5 / 6 还需要先写关卡内容（房间、证据、对质）。

## 9. 别让每一关都是搜集线索（2026-10-17 用户反馈）

跑通五关之后最明显的感受：**每一关的开头都一样**——走进房间、挨个点东西、捡线索、去电脑搜词、把手账里的卡片拖进句子、进沙盒、对质。搜集线索是共同的底，但不能当主菜。下面的壳子都做成 `public/case-mini-<kind>.js` 那样的独立模块，由 `game.puzzle.core` 指定用哪一个；**没有 core 的关仍走现在的搜索+推理板**，一关一关换，不用推倒重来。

### 六个委托轮起来

| 委托 | 主壳子 | 为什么是它 |
|---|---|---|
| 小林 · 小账本 | 审读台 | 隐私条款天生是「承诺 vs 行为」的核对 |
| 阿哲 · 天气小助手 | 排除网格 | 密钥藏在文件堆里，本来就该「圈出来」 |
| 小雨 · 像素计算器 | 输入序列 | 彩蛋就是按键序列，已经做了 |
| 朵朵 · 种田存档 | 存档编辑（已有沙盒） | 改数值算校验，本身就是玩法 |
| 周姐 · 便签版本 | 时间线排序 | 版本对比的天然形态 |
| 王奶奶 · 手电筒 | 数据流连线 | 权限最小化就是「别让数据走到出口」 |

**复勘（副本）直接复用同一个壳子、换更狠的参数**：审读台撤掉高亮、网格只给数字不给文件名、连线加上自启动偷线、序列把残页改错。壳子写一次，六关加十八个复勘都能用——这也正是 `docs/progression.md` 里「一层玩法、多层参数」的落地方式。

### 先做哪三个

1. **时间线排序**（周姐）：她的样本本来就是两套文件，壳子和内容互相成就，而且这一关还没做，顺手一起出。
2. **数据流连线**（王奶奶）：视觉最跳，手机横屏也好点，权限话题讲得比清单直观。
3. **审读台**（小林）：要改已经能玩的关，收益大但动得深，放最后。

每个壳子的共用部分：键盘可玩、手机横屏、`case-session` 统一管存档/星级/难度，壳子只负责「这一小时手上在干什么」。
