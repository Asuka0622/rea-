## 3. 尺度（这张图最重要的验收项）

| 东西 | 世界单位 |
|---|---|
| 成人可见身高 | 56–64 |
| 儿童 | 略矮，约 44–52 |
| 门净高 / 净宽 | 72–88 / 48–64 |
| 主路 / 支路 / 无障碍最窄 | 160–224 / 96–128 / 64 |

对照方法：把人（64 单位）放到门口并排比。**人比门矮一截**才对；人齐门顶就是画小了。

## 4. 构图与气氛

中心是**集合、相遇、问路**的地方，不是商业街：

- 中央喷泉（约 300×300 世界单位），周围一圈石铺广场，留出能绕行的宽路。
- 四条路从广场接出，形成环路；不要一条大直线穿到底。
- 树荫、长椅、路灯、花盆、落叶；广场边缘可坐、可看。
- 建筑密度克制：单屏（640×360）最多并列 1–2 栋主要建筑，留宽步道与院子。
- 不烘焙人物、问号、按钮、店招文字；店招由代码画。

## 5. 候选图与它的偏差（重要）

`docs/art/review/regions/center-v2-candidate.png`（2560×1440）是按上面的构图生成的**风格样板**；
`center-v2-blockout-check.png` 是同一张图叠上第 2 节的建筑框，可以直接看出**生成图的建筑位置与坐标有明显偏移**
（左上事务所在图里偏左、右上图书馆偏内、右下摊位被树占住）。

结论：**这张图只能定风格与气氛，不能当运行图**——门对不上坐标，玩家会站在空地上。

正确做法：**以第 2 节的坐标为准重画**，构图可以参考候选（喷泉居中、四路、秋树、暖光）。
如果要在重画前先验证工程链路，可以用程序画的灰盒（见第 6 节），但那不是交付物。

## 6. 接入要改的四处（工程侧，给排期用）

1. `game-regions.js` 的 `REGION_SIZE` 从 960×540 改 2560×1440，五个区的 `spots` 坐标全部换成 plan 坐标。
2. 每区一张碰撞图 `public/art/pixel/regions/town-<zone>-walk.json`（现有五张都是 960 图导出的，必须重导）。
3. 人物尺度：`.game-stage` 的 `--person-h` 从 32px 改 64px、`--person-w` 改 32px（已抽成变量，一处切换），切完按第 3 节验收。
4. 相机与出口触发：出口带宽 160、落点离边界 48，切换加短暂再触发锁，不能来回弹图。

这四处必须**五个区一起切**——只换一区会让区域切换时的落点全部错位。
