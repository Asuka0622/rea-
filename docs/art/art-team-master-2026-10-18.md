## 10. 新增：地图、人物与光源统一（2026-10-18）

目标：路米和NPC进入树荫会变暗，走到暖色路灯下会被暖光染亮；脚底有落地阴影，房屋能够挡光，前景能够遮住人物。**不用引入游戏引擎也可以实现；这是待接入能力，当前不能声称已经完成。** 美术负责分层、光源位置与遮光标注，程序负责按人物位置合成光照。

### 10.1 先做样板，不全镇重画

第一批只选中心广场一段：一栋有亮窗的房屋、一盏路灯、一棵有树荫的树、路米及一位普通NPC。做同构图的白天/夜晚合成参考，再通过独立图层切换；示意合成图不是替代分层交付。

先检查已有底图、glow、wet、front和人物素材；能用的直接复用。对于阳光和地面阴影已经画死的旧图，记录局限；只局部返工样板，不要求立即重做全部九区。

### 10.2 地图分层交付

每区以 `public/art/pixel/regions/town-<zone>-*` 命名，<zone> 对应九区id。母版3840×2160，游戏空间2560×1440，共享1280×720基础格；所有层同画布、同原点、同裁切，不得各自居中。

|层/数据|建议文件|交付要求|
|---|---|---|
|基础颜色|`-base.png`|完整不透明底图，保持像素材质和形体；避免把强烈单一方向阳光、灯晕、人物影子永久画死。不是要求画成没有层次的平涂图。|
|前景遮挡|`-front.png`|屋顶、树冠等独立真实alpha；与对应物件的脚底/深度线关联。遮住人物和挡住光是两件事，不能只交一层就说两者都完成。|
|阴影参考/静态阴影|`-shadow.png`|透明底黑色/中性暗色alpha，边缘按像素风；角色影子不烘焙进地图。白天方向性投影与树荫单独标类型，不把夜晚关不掉的太阳影子留在底图。|
|发光源|`-emissive.png`|透明底，仅灯泡、灯笼、窗玻璃、招牌发光部分；不要把整面墙、路面和邻近人物涂进来。原有广域glow可留作合成参考，不代替光源坐标。|
|地形遮光|`-occluders.json`，必要时附mask预览|房墙、围墙、大石块等遮光多边形及估计高度。墙体实遮光、树冠可部分透光、栏杆另标，不从整张插画明暗自动猜。若交mask：白色不透明表示遮光，透明表示无标注；mask只是数据，不作为可见背景。|
|树荫/区域明暗|`-shade-zones.json` 或同画布透明mask|标树荫、门廊、屋内等区域，注明影响人物和地面的范围/强度，进入退出平滑过渡。|
|光源清单|`-lights.json`|每盏灯/窗/发光物的稳定id、世界坐标、色温/颜色、范围、强度、启用条件与所属物件；不是只交一张“夜景变暗图”。|

室内仍按320×180逻辑布局处理，实际导出倍率逐件写明；同样分窗光、灯、前景与物件，不套九区大地图坐标。

### 10.3 人物要求

- 所有角色保持原来的固有色、衣服和身份；不逐帧烘焙固定路灯高光，不为每盏灯另画整套人物。路米旧图与新NPC先按可见身高校准。
- 每个动作统一 `footAnchor`（脚底接地点）、可见身体框与透明边距。说话、待机、左右走时接地点不能漂移，否则阴影会脱脚。
- 阴影独立处理：普通阶段由程序画小型像素椭圆接触影，随脚底走；跳跃时可缩小/变淡，不能把人物整体抬起而影子也悬空。特殊形状才另交alpha影子贴图。
- 灯光颜色应作用于人物的真实alpha区域，不要把矩形帧底染出来。头像属于对话UI，不强行随地图灯光变得看不清。
- 本阶段**不要求全员法线贴图、逐帧手绘动态影子或大量白天/夜晚人物版本**。若后续需要精确左右受光，再单独试做路米一组帧的法线/高度图，确认有效后扩展。

### 10.4 光源数据约定

所有坐标单位明确写 `game-world`，不能一份用母版像素、一份用游戏单位。地图母版像素转游戏单位是×2/3，但从美术基础格放置可以直接输出整数游戏坐标；有精确锚点时不要靠试缩图猜。

示例仅展示字段，**不是已验收的灯位**：

```json
{
  "coordinateSpace": "game-world",
  "worldSize": [2560, 1440],
  "artMasterSize": [3840, 2160],
  "lights": [{
    "id": "center-lamp-sample",
    "kind": "point",
    "position": [1560, 760],
    "height": 100,
    "radius": 180,
    "color": "#ffd49a",
    "intensity": 0.7,
    "activeWhen": ["evening", "night"],
    "castsShadow": true,
    "owner": "lamp-sample"
  }],
  "occluders": [{
    "id": "wall-sample",
    "polygon": [[1600, 620], [1700, 620], [1700, 660], [1600, 660]],
    "height": 96,
    "transmission": 0
  }]
}
```

物件摆放锚点、光源发光点和人物脚底可能不同；分别写明，不能把一盏高路灯的脚当作发光位置。窗口可用矩形光域，不强行当成一个圆点。树冠透光率由接入样板调整，不假装已有真实物理测量。

### 10.5 程序与美术分工

- 程序：统一日夜环境光；使用Canvas/WebGL或现有渲染层，让人物与地面共享光场，按位置计算亮度/染色；按遮光数据限制穿墙光；接触影、可见光源筛选与镜头换算；UI保持可读。
- 美术：画干净的固有色、独立发光与阴影/前景层、标光源与遮光轮廓，提供昼夜同构图参考。没有代码接入前只标待验收。
- 首阶段做可信的2D受光与简化阴影，不承诺3D全局光照、无限实时投影或所有天气组合的完整重打光。只处理可见区域和附近灯，避免一次加载九张母版及全镇光源。

### 10.6 样板验收，缺一不算通过

1. **白天进树荫**：人物与地面同步变暗，脸和衣服仍辨认，不会人物始终发亮。
2. **夜晚走近路灯**：人物渐渐染上灯色；离开恢复环境色，没有整块矩形染色和突然闪变。
3. **墙与门廊**：灯不能穿过实体墙照亮另一侧人物；前景遮挡与人物深度顺序正确。
4. **移动与转向**：脚底影跟随接地点，左右行走、待机切换不跳位；镜头滚动时光源不跟着屏幕漂。
5. **切换昼夜/雨天**：白天灯光关闭，夜晚窗口正确亮；雨天可用独立湿地反光层，不残留白天强烈日光条纹。尚不覆盖的状态如实标明。
6. **多角色与横屏**：路米和一位NPC站同一灯下遵守相同规则；桌面及手机横屏可辨人物、提示与路径。实机截图带光源id和人物位置，不能只交一张漂亮的静态夜景。

优先级：作为C批“中心地图样板”的一部分，与人物比例一起验收。通过样板后再推广到其他区；不阻塞先用占位图跑流程。


## 11. 新增：人物、NPC与天气联动（2026-10-18）

这是正式需求，包含美术、关卡与程序三方工作；**写入需求不等于天气联动已实现**。路米与NPC必须处在同一个天气世界里，不能只有屏幕上飘雨、人物照常站着。与第10节共用光照、世界坐标、脚底锚点和遮蔽数据。

### 11.1 先验证的天气与角色反应

|状态|路米/人物视觉|NPC行为与对白|场景配合|
|---|---|---|---|
|晴天/阴天|统一环境亮度与色调，保持角色可辨；不另画全员换色版本|普通日程；对白可评论天气，避免每次重复|阴天减弱方向日影，树荫与门廊照常参与受光|
|小雨/大雨|露天有低成本雨滴/脚边水花、衣物湿润叠层；伞或雨衣先只做样板，不默认人人配齐|户外闲逛者就近避雨；可撑伞的角色沿可达路线行动；摊主按设定收摊或转移到有顶位置|屋内/屋檐下不落雨；水花只在适用地面，门廊不与街道同样湿|
|雷雨|雷光短暂影响地面与角色，限制强度/频率并提供减弱闪光设置|可短暂停步、惊讶，再到安全避雨点；对白不应每次雷声都触发|雷声与闪光由程序配合；不能长时间遮盖路径和互动提示|
|风|头发/衣摆轻摆先复用现有有效帧，持伞姿势与朝向一致|必要时停留避风；叶片随风，不能让所有角色一直高速抖动|风向与落叶/雨丝方向一致；不把特效烘焙进人物|
|雪/寒冷（后续）|脚印、围巾/搓手/呵气只列扩展候选，先确认季节系统与资产再排产|缩短户外停留，进入暖处；对应寒冷对白|雪地脚印与积雪范围对齐，不因本条立即重画全季节人物|

第一阶段只落地晴/阴/雨的中心广场样板；雷雨与风随后验证，雪列后续。天气不会默认扣血、降速、降低操作精度，也不加入未确认的生存系统。

### 11.2 美术交付：先一个角色，避免全员重复画

- 样板组合：路米＋阿桃（营业）＋老周（户外活动），优先认领已有站立/走路/说话/工具动作，缺少的再补。
- 必需候选：雨伞独立透明道具（握持点、开合状态、前后遮挡关系）；露天脚边水花短动画；一组NPC避雨待机/收手动作。湿衣、雨衣、风中衣摆按样板效果决定是否新增，不能先给12人批量出全套。
- 持伞若用叠层，按下/上/侧方向交付握点与前后层；左右是否镜像要标明。伞下身体、头部、手臂不能穿帮，不能把伞柄固定在屏幕坐标。主角撑伞不得遮住附近互动目标与提示。
- 像素粒度、帧网格、脚底锚点和动作时长沿第2节；雨滴、湿润和光照叠层作用于真实alpha，不出现矩形人物底块。室内和对话头像不叠整屏雨。
- 每个避雨点标稳定id、所属区域、覆盖多边形、站位、容量、入口与营业用途；标树冠只减雨还是完全遮雨。不能默认树下等于雷雨安全点。先用已有门廊/有顶摊位，不为避雨额外铺满小屋。

### 11.3 程序逻辑：天气、日程、任务共同决定行为

- 统一天气状态提供类型、强度、风向、过渡与区域；粒子、光照、声音、地面和角色读取同一状态。室内有独立遮蔽判定，切区后延续天气，不每次随机重开。
- NPC用普通日程 → 天气重规划 → 走向避雨点 → 到达待机 → 雨停后恢复的明确流程。下雨要走过去，不能瞬移；先查路可达与避雨点容量，找不到就选备用站位或留在可达安全位置，避免多人重叠、卡门与反复折返。
- 天气采用强度阈值/过渡和最短停留时间，避免晴雨切换时来回跑。避雨点可散布NPC，但交互距离、前景遮挡和任务追踪须同步更新。
- 正在对话/教学/演出时先完成当前互动，再切换日程；任务关键NPC在开放时段必须可找到。转移后地图/追踪提示新位置或提供屋檐下对话，不让天气使委托失效，也不强制玩家等雨停。
- 路米由玩家控制，不自动跑去避雨；进入屋檐/室内时雨滴、水花和湿润效果按遮蔽与地面调整。伞的可用状态和切换入口在接入时明确，不默认为已有装备功能。
- 雨停后逐步收伞/恢复活动，湿地可延迟变干；不把晴天、夜晚、雨天状态互相覆盖。环境音与雨声在室内衰减，保留对话可读性。
- 日程进度与天气时间基准按现有存档策略接入；读取旧存档要有默认值。特效数量有上限，离屏NPC简化更新，手机横屏验证不卡顿。

### 11.4 对白与交互要求

每位样板NPC至少提供“开始下雨 / 避雨中 / 雨停恢复”三种短句，按角色身份写，不给全员同一句。台词交JSON/文本，不能画进素材；触发设冷却并避免连续重复。任务对白优先于天气闲聊，已读剧情不因下雨重播。

示例候选，后续结合完整人物设定核对：
- 阿桃：开始下雨“先把面包挪到檐下，别淋湿了。”；避雨中“照常卖，站里面些。”；雨停“地上滑，慢点走。”
- 老周：开始下雨“鸽子都躲起来了，我也去檐下歇歇。”；避雨中“等雨小点再出去。”；雨停“好了，出去透透气。”

### 11.5 联动验收（必须实机，不能只验静态雨景）

1. 晴转雨：路米仍可操作；NPC结束手头互动后沿路避雨，伞/手/步态无穿帮，雨不落进屋檐。
2. 同一屋檐内外：人物、地面、水花、雨声和受光均符合遮蔽，脚底影不脱离；镜头移动后天气与角色坐标仍一致。
3. 暴雨/夜雨：人物可辨、暖灯受光合理；闪光可减弱，粒子不挡阅读/交互。未接雷雨时如实标待做。
4. NPC迁移：任务仍能接取/完成、追踪地点更新，商店有明确营业状态；多个NPC不堆在同一个入口。
5. 雨停/快速切换：收伞和恢复日程不抽搐、不重复刷台词，不把玩家传送，不遗留室内雨或浮空水花。
6. 读档/切区/横屏：角色状态可恢复或安全回退，无卡死、无输入失效；记录各样板天气组合的截图/短视频与实际支持范围。

交付归属：美术画角色/雨具/局部效果并标锚点；关卡布遮蔽区、避雨点和通路；程序实现天气状态、日程/寻路、对白、任务兼容与合成。此项并入C/D批样板验收，通过后再按需扩全镇。

### 12.3 命名与状态元数据

### 12.4 组合与复用验收

- 同机位、同人物位置检查晴日/阴日/夜晚/夜雨，主体比例、门口、出口、碰撞锚点不漂移；天气和时间必须可以叠加，不能一换季就把夜灯和NPC状态清掉。
