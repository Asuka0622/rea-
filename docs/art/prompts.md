# REA 工作台 · 美术需求清单与提示词（全像素风）

> 给负责出图的 AI 看的说明。新手模式现在是一个全屏像素小镇游戏：首页是小镇地图，点房子进入室内，路米在底部对话框里说话，功能在木框窗口里打开。下面列出了**所有需要出图的地方**。没有图的位置，界面暂时用 CSS 画的简单像素场景或小人代替；图放进指定文件夹后会自动显示，不用改代码。

> **当前美术状态**：五张分区图和十张必需室内图完整覆盖 `autumn-clear-noon`、`spring-clear-morning`、`spring-clear-noon`、`spring-clear-sunset`、`spring-clear-night`、`spring-rain-morning`，共 6/48 种组合；其余 42 种与可复用叠加层尚缺。新增生图原稿按原始 1672×941 分辨率保存在 `public/art/source/`，游戏尺寸版本另存。已完成人物素材保持原样。

## 0. 先看这里

**场景风格更新**：地图、建筑、室内、道具与小动物统一采用用户提供的像素场景参考方向：繁茂的自然环境、层叠树冠与岩石、清楚的方块像素簇、浓郁明暗、蓝绿色水面、赭黄色土路、红金色季节植被。采用高位 3/4 俯视，画面细节丰富但留出可走空间。不要照搬任何现成游戏、角色或场景。**只有对话头像用二次元立绘**，放在像素风木框对话框里。

**全局季节、天气与时段**：当前暂定四季为春、夏、秋、冬；天气为晴天、雨天、雪天；时段为早晨、中午、傍晚夕阳、夜晚。地图与对应室内必须共享同一个状态：植物/落叶/积雪、地面湿痕、窗外景色、阳光方向、室内窗光与灯具亮度都要吻合。文件名或交付清单标明 `season-weather-time`。季节通过季节版底图表达；时段与天气可用可叠加的光照/天气效果复用，但会改变室内物件或地面细节的地方需要单独变体。**当前实际完整覆盖上述 6 种组合，其余 42 种尚缺，不能声称覆盖全部状态。**

**细节一致性**：晴天不画雨伞、雨滴或明显积水；雨天要有湿润路面、窗上雨痕，室内可出现收起的雨伞/雨衣；雪天要有积雪、雪靴或暖炉等合理细节。春季有新芽和花苞，夏季枝叶浓密，秋季有黄红叶与落叶，冬季有裸枝和积雪。早晨光线偏柔且低，中午窗光明亮、以日光为主，装饰灯仅留低亮暖光；傍晚使用金色夕照和较长阴影，夜晚以冷色窗外环境和室内实际灯源照明。设备类火光（如锻炉）要符合房间是否正在工作。室内摆件、植物、窗外景色、地面与光源必须和当前地图状态一致；禁止只换整体色调却保留不合时令的细节。

**三条规则**
1. 角色和场景全部原创。提示词里**不要写任何现有游戏、动漫、角色或画师的名字**（包括星露谷），只描述想要的样子。
2. 同一类图用同一段"统一风格词"。第一张满意后，把它当参考图（或固定种子），保证整套画风一致。
3. 像素要整齐：每个像素格大小一致，没有模糊和抗锯齿。AI 出的"像素画"常常格子不齐，出图后用图片工具按**最近邻**缩小到下面写的"原始尺寸"，交付原始尺寸的文件。

**两种画法**：
- **对话头像是二次元立绘**：高清插画，界面自动裁出头肩、缩小放进木框。
- **场景和场景里的小人是像素画**，界面放大 3 倍显示（1 个画面像素 = 3 个屏幕像素）。场景和小人必须按同一个像素大小来画，小人站进场景里才协调；所以小人很小（16×32），只表现发型、发色、衣服颜色这些大特征。

**交付**：PNG，文件名全小写、用短横线，放进指定文件夹。人物头像和图标要**透明背景**。

**已有的东西**：`public/art/portraits/` 里已有路米 4 个表情、小林 3 个表情的二次元立绘，已经在用了。其余角色请保持同样的画风；画小人时也按这些立绘的人物设计（发型、发色、服装、配饰）。

### 规格

- 竖版 3:4，和已有的路米、小林一样大（约 1086 × 1448），**透明背景 PNG**。

- 同一角色的所有表情：同一套衣服、同一角度、头的位置和大小一致，只换表情和手势。
- 文件名：`<角色>-<表情>.png`，放进 `public/art/portraits/`。之后运行 `python -I scripts/prepare-portraits.py` 生成网页用的小图（小克来做也可以）。

| 普通 | normal | 平时说话 | 平静微笑，看向前方 |

## G. 场景里的小人（16 × 32，透明背景）

> ✅ **路米的做法就是标准做法**：直接交**高清的原图精灵表**（像你画的路米那张：透明背景，一行一个动作，从上到下依次是待机 2 帧、向下走 4 帧、向上走 4 帧、侧面走 4 帧、说话 2 帧，同一行的帧从左到右排）。**不要自己缩小到 16×32**，缩小会糊。把原图交给小克，小克用 `scripts/import-sprite-sheet.py` 切帧、对齐脚底、生成游戏用的精灵表，界面会平滑缩放显示，并按走路方向切换正面、背面、侧面。

和场景同一种像素粗细，站姿正面或略侧，脚踩在画面底边。每个角色一张，文件名 `sprite-<角色>.png`（角色前缀同 A：lumi、kobayashi、azhe、xiaoyu、duoduo、zhoujie、grandma）。

中文：
> 温馨农场生活类像素游戏里的小人角色，像素画，原始尺寸 16×32 像素，全身站立，正面略侧身，大头小身体的可爱比例，清晰的方形像素点，无抗锯齿，有限调色板（约 12 色），深色像素描边，透明背景

English：
> small character sprite for a cozy farm-life pixel game, pixel art, native 16x32 pixels, full body standing, front view slightly turned, cute big-head proportions, crisp square pixels, no anti-aliasing, limited palette of about 12 colors, dark pixel outline, transparent background

外观按 A 的角色描述，只保留最显眼的特征，例如路米：薄荷青短发、米白披风、浅灰卫衣、脖子上的耳机。

## J. 人物动画（逐帧，每帧 16 × 32）

**用逐帧动画，不要用骨骼动画。** 骨骼动画会把图片旋转、拉伸，像素格会被打乱、变糊；像素游戏（包括星露谷）都是一帧一帧画的。

每个角色一张**精灵图**（所有帧排成网格的一张图），加一个同名的 JSON 说明文件：

- 文件：`anim-<角色>.png` 和 `anim-<角色>.json`
- 每帧 16 × 32，透明背景，帧与帧之间不留空隙；每一行是一个动作，从左到右是这个动作的各帧
- 角色的脚在每一帧里都站在同一条线上（帧底部），身体位置不要左右漂

**现在界面使用的简化格式**（路米已按此完成，见 `anim-lumi.png` / `anim-lumi.json`）：第 1 行待机 2 帧（第 2 帧眨眼），第 2 行走路 4 帧；朝左由界面镜像。下面四方向的完整格式以后再做。

| 行 | 动作 | 帧数 | 说明 |
|---|---|---|---|
| 1 | idle（待机） | 2 | 轻轻呼吸或眨眼 |
| 2 | walk-down（向下走） | 4 | 朝向镜头走 |
| 3 | walk-up（向上走） | 4 | 背对镜头走 |
| 4 | walk-side（侧面走） | 4 | 朝右走；朝左由界面镜像 |
| 5 | talk（说话） | 2 | 张嘴、手势（可选） |

JSON 格式（每个动作的行号、帧数、每帧时长）：

```json
{
  "frame": [16, 32],
  "animations": {
    "idle":      { "row": 0, "frames": 2, "ms": 500 },
    "walk-down": { "row": 1, "frames": 4, "ms": 150 },
    "walk-up":   { "row": 2, "frames": 4, "ms": 150 },
    "walk-side": { "row": 3, "frames": 4, "ms": 150 },
    "talk":      { "row": 4, "frames": 2, "ms": 250 }
  }
}
```

提示词在 G 的小人提示词后面加上：
> 精灵图，同一个角色的多帧动画排成网格，每帧 16×32 像素，第一行待机 2 帧，第二行向下走 4 帧，第三行向上走 4 帧，第四行侧面走 4 帧，第五行说话 2 帧，帧之间对齐、脚踩同一条底线
