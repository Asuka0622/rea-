## 目标

完成仓库当前美术需求清单里的所有有效素材，保持比特镇现有画风统一；复用并验收已有素材，缺项再制作。完成后逐项校验文件、尺寸、透明通道、精灵帧布局和清单状态，并把仍需游戏内布置/验收的项目明确标出。

## 先读这些文件

1. `docs/art/asset-requirements.md`：当前正式需求、优先级、暂停项和统一交付规则。
2. `docs/art/requests-case-rooms.md` 与 `docs/art/requests-case-rooms.csv`：委托房间逐件物品、坐标锚点和现状。

4. `docs/art/list.md`：全项目美术范围。
5. `docs/art/prompts.md`、`docs/art/room-scale.md`：风格、像素比例和场景约束参考；与 `asset-requirements.md` 冲突时以当前需求文件为准。
6. `docs/art/delivery-2026-10-17.csv`、`docs/art/inbox.md`：已有素材登记和来源。

## 风格约束

- 场景沿用比特镇现有的细腻像素环境：温暖木材、分层树冠、水面和秋季红金植被；默认场景基准为秋季晴天中午。
- 人物与小人沿用已有角色设计及像素精灵比例；同一角色的发型、服装、颜色、轮廓和阴影保持一致。
- 用户明确指定小克直接采用 Claude Code 的 Clawd 橙色像素蟹形象：方块橙色蟹身、深色方眼、短钳和小腿。小克已生成六表情头像、4×5 动画表和怀表图标；继续沿用现有文件，不改回白色机器人或薄荷青屏幕方向。
- 房间背景不烘焙独立调查物品；动态 UI、文字、数字、血条、提示和粒子交给代码。图像不生成伪中文或可读小字。
- 透明素材必须有真实 alpha。按清单的逻辑尺寸和 2 倍像素密度交付；动画逐帧同尺寸、基线一致，并附 JSON。
- 已有素材先核对与复用，不重复出图。最终运行文件放 `public/art/`；源图、候选和验收预览放 `docs/art/review/`；同步更新交付 CSV。

## 给新任务的执行指令

> 接续 rea 仓库的美术素材工作。先读取本交接文件和上列需求文件，并检查当前 Git 分支、工作树和各清单目标文件。保留已经生成的 Clawd 小克资产及其他现有工作，不覆盖用户改动。盘点所有未完成、未暂停、未废弃的有效需求；先复用、验收已有源图，再按优先级完成缺项。直接把合格运行素材放进 `public/art/`，将源图与候选放进 `docs/art/review/`，为精灵表交 JSON，并同步更新交付 CSV 与状态说明。完成后按清单核对尺寸、命名、alpha、帧数和锚点，汇报已完成、待游戏内验收及明确阻塞项。不要把旧汴京/中世纪路线、废弃比比或其他标记为暂停/废弃的资产重新纳入。

## 云端执行注意

本交接文件只记录项目状态，不会自动上传当前工作树。启动 Codex 云端任务时，选择一个包含本地美术改动的分支；云端仓库若看不到这些文件，先同步该分支再继续。
