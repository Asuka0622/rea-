# 小游戏素材需求：七种玩法（2026-10-18）

小游戏跑在案件实验室面板里。本清单记录替换占位所需的像素演出素材，以及接入和验收状态；塔防、经营、卡牌已接入，节奏与管道素材待接入，格斗与时间线目前各保留一张概念图。玩法本身的设计见 [minigame-genres.md](../minigame-genres.md)；委托房间的素材不在这里，见 [requests-case-rooms.md](requests-case-rooms.md)。

## 一、统一规格（这一批都适用）

- **显示区域**：实验室面板，可视区宽约 640–720、高约 360（单玩试玩页最大 760 宽）。**全部按 2 倍像素密度出图**：显示 32 单位宽就交 64 像素宽，接入方按最近邻缩放。
- **满幅背景与带状件**：满幅按 1280×720（逻辑 640×360）；横向带状件宽 1440、可平铺可居中裁切，**关键装饰别只画在两端**。
- **风格**：与已接入的委托房间同一像素颗粒（参照 `case-room-*.png`）；小人参照现有 4×2 精灵表的 Q 版比例。经营那一款单独走「日式 Q 版等距」风，见第三节。
- **透明底、不写可读文字、不画 UI**：问号、数字、判定文字（完美/还行/漏）、连击、血条、按钮、进度条、牌面标题全部由代码绘制。卡面与纸张上只画**能认出的物件**，不画文字。
- **文件**：运行进 `public/art/pixel/minigames/`，源图进 `docs/art/review/sources/`，命名 `mini-<玩法>-<内容>.png`；精灵表按 [asset-requirements.md](asset-requirements.md) 第 7 节格式附 JSON。
- **交付与验收**：仍按 asset-requirements.md 第 8 节的 CSV 流程；接入后在 `?debug&mini=<case>&kind=<kind>` 试玩页逐个看，并跑一遍对应委托关，问号、站位、代码文字不能被新图挡住。

## 三、经营 · 权限的代价（试玩 `?debug&mini=flashlight-apk&kind=manage`）

**视觉方向：日式 Q 版 3D 经营游戏**（那种大头小人、糖果色、店铺慢慢变热闹的手游）。我们不做真 3D，用像素做同样的观感，四个要点：**等距 45° 俯视、Q 版大头小人、店铺随经营变化、金币与表情粒子**。

| 内容 | 文件 | 交付尺寸 | 要求 |
|---|---|---|---|
| 主场景 | `mini-mg-office.png` | 1280×720 | 手电筒公司内景，**等距视角**一间店面：前台、老板桌、手电筒货架墙、一扇窗、一块**空的广告位框**。不画顾客、不画文字 |
| 广告贴画 ×3 | `mini-mg-ad-lamp.png` / `-contacts.png` / `-nearby.png` | 各 96×64 | 灯泡广告（正经）、「找朋友」（读了通讯录后）、「附近」（开了定位后）；代码按当前权限组合往广告位里换 |
| 顾客小人 | `anim-mini-mg-customer.png` + `.json` | 20×28/帧 | Q 版大头，两行：男/女各 walk 4 帧 + 满意离开 2 帧 + 皱眉离开 2 帧 |

| 风险警铃 | `mini-mg-alert.png` | 32×32 | 问询/通报时在标题旁晃；摇摆由代码做 |
| 通报文件 | `mini-mg-notice.png` | 48×64 | 一张盖红章的纸；章是图形，不写字 |
| 日夜变体 | `mini-mg-office-evening.png` | 1280×720 | **P2**：先看代码调色够不够，再决定画不画 |
