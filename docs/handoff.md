## 1. 游戏现在有什么

新手模式是一个全屏像素小镇游戏，跑在网页里，REA 工作台原来的功能都装在游戏的木框窗口里。

| 系统 | 现状 | 代码 |
|---|---|---|
| 小镇地图 | 五张 960×540 分区图已接入：中心广场、住宅区、手艺街、北区、南岸。走到路口进入相邻分区；地图（M）按分区列出所有地点，可以跨区寻路 | `public/game-regions.js`、`public/game-shell.js` |
| 碰撞和遮挡 | 由脚本按图自动生成：树、水、石头挡路，人物能走到树和房子后面 | `scripts/build-walkmap.py --region <名>` |
| 室内 | 整间显示，人物可以走动，走到主要家具前按 E 办事，走到门口回小镇 | `game-shell.js` 里的 `ROOMS` |
| 任务 | 主线「停摆的钟楼」+ 侦探事务所支线（REA 6 个案例）；任务日志（J）、追踪栏、目标房子头上的「!」 | `public/game-quests.js` |
| 主线进度 | 序章、第一章「打开钟楼」可玩；第二章起显示「制作中」 | 同上 |
| 小游戏 | 第一章的二进制灯、零件归类、两个抽屉；三档难度各有区别 | `public/game-minigames.js` |
| 技能树 | 像素 RPG 天赋树（K），五条主干各一页，每页 14 个技能，共 70 个，就是整套课程大纲 | `public/game-skills.js`、`public/game-skilltree.js` |
| 成就 | 25 个成就，在技能树界面最右边的「成就」页 | `public/game-achievements.js` |
| 导航栏的钟 | 跟主线联动：停摆（11:58）→ 不准 → 正常 | `game-shell.js` |
| 手感 | 打字机对话（每个角色音高不同）、合成音效（可关）、进出门淡入、飘落的秋叶、水面流动 | `public/game-sound.js`、`public/game-water.js` |

**命名规则（新加内容时请遵守）**
- **技能名要直白、一看就懂**：「数据流向」「域名和 DNS」「时间同步」「机器学习」。
- **有趣的名字放进成就**：「芝麻开门」「大家来找茬」「手电筒想看通讯录？」。

## 2. 游戏引擎：正式版迁移到 Godot 4（2026-10-16 定）

**测试版继续用网页做完；正式版迁移到 Godot 4。**（这一节取代 10-15 写的「现在不用，只把地图层换成 Phaser 3」。）

### 两个阶段
1. **测试版（现在）**：在现有网页版上做完最低主线（序章、六个时代各一小段、结局）和 REA 侦探支线。网页版改起来最快，用来验证玩法、剧情节奏和三档难度。侦探事务所的预告测试版已经可以打包。
2. **正式版（测试版做完之后）**：用 Godot 4 重新搭。估计 12 到 18 个工作日。

### 为什么正式版要用引擎
- 地图上会有几十个 NPC 和小动物、四季、天气、昼夜光影、逐帧动画。引擎现成提供精灵动画、按远近自动排序遮挡、瓦片地图、碰撞、粒子、镜头和灯光。
- 正式版要考虑手机、桌面，甚至主机发布。Godot 打包这些平台比网页套壳更稳。
- Godot 免费开源，体积小，2D 像素游戏支持好。

### 迁移前要准备好（测试版阶段就按这个写）
- **数据和引擎无关**：任务、对话、关卡、委托（`samples/cases/*/workbench-case.json` 里的 `game` 和 `puzzle`）、技能、成就都写成 JSON 数据，不写死在网页代码里。正式版直接读同一份数据。
- **教学案例的报告预先算好**：正式版不在玩家电脑上跑 REA，报告和代码片段跟着游戏一起发布。
- **美术按引擎友好的格式交付**（见下）。

### 带过去的，要重写的
| 带过去 | 要重写 |
|---|---|
| 设计文档、剧情、关卡和委托数据 | 界面（对话框、窗口、任务日志、技能树） |
| 全部美术 | 地图、人物移动、碰撞（改用 Godot 的瓦片和物理） |
| 教学案例和预先算好的报告 | 小游戏和解谜关卡的交互 |
| 测试里定下的难度和节奏 | 存档 |

### 还要评估的
- **写真代码**：网页版用浏览器跑 Python（Pyodide）、C/C++（JSCPP）和 JavaScript。Godot 里要换方案：内嵌 WebView、带一个小解释器，或者只在桌面版调用本机环境。
- **动手实验**：网页版把样本程序放进沙盒框架里真的运行（`public/case-labs.js`）。Godot 里可以改成按样本代码写好的行为脚本，或者内嵌 WebView。
- **REA 真实分析**：正式版游戏里不需要。工作台作为独立工具或「专业模式」保留。

### 对美术的影响
现在的交付格式都能直接用：
- 分区地图：整张 PNG，960×540 原始尺寸。
- 人物和动物：高清原图精灵表，一行一个动作。
- 逐帧小动画：横排精灵表，透明背景（第四批）。
- 建筑、钟楼这类叠加物：透明背景 PNG。

**正式版可能新增的要求**（到时另外写清楚，现在不用准备）：
- 早中晚光影：窗户、路灯这类「会发光的部分」单独一层。
- 瓦片地图：地面、路、水画成可以拼接的瓦片。
- 解谜关卡的现场图：物品单独一层，方便做点击区域和高亮（侦探委托现在就需要，见 `docs/art/prompts.md` 第六批）。

## 3. 哪些是代码做的，哪些需要画

**已经用代码做了，不用画**
- 水面流动：自动找出水面，让原图的波纹轻轻晃动，再加上闪光点。
- 飘落的秋叶、进出门淡入。
- 技能树的宝石、锁、连线，成就的奖杯：用代码一格一格画的像素图。
- 钟楼：在北区用代码画了一个灰色小塔占位，等第三批 P 节的钟楼图。
- 没有立绘的角色说话时：用写着名字首字的木框代替（比如「铁」）。

**还需要你画的（按优先级）**
1. **第三批**（`docs/art/prompts.md` P–V 节）：
   - 钟楼（停摆版、正常版）和钟楼内部
   - 第一章道具
   - 铁叔（立绘 + 精灵表）
   - 导航栏小钟
   - 比比、星博士
   - 第二到五章的道具
   - 技能和徽章图标
2. **第二批里的主线角色**：阿木、阿信，以及其他 NPC。
3. **第四批**：让地图动起来的逐帧小动画（喷泉、烟囱、水车、跳鱼……）。

**可选**：技能树的 70 个技能现在用一个像素汉字当图标（比如「01」「存」「锁」）。如果你有余力，可以给技能画 24×24 的像素小图标，文件名 `public/art/pixel/skills/<技能 id>.png`，技能 id 见 `public/game-skills.js`。画好的会自动替换汉字，没画的保持汉字。

## 4. 协作约定

- 每次动手前 `git pull`，看一眼 `git log`，避免和小克改到同一个文件。
- 美术文件放在 `public/art/` 下对应的文件夹，文件名全小写、用短横线。分区图换了以后，告诉小克重新跑碰撞脚本。
- 代码由小克改；如果你需要改代码（比如调某个素材的位置），在提交说明里写清楚改了什么。
- 测试一律在沙盒里跑：`node sandbox.mjs` 或 `npm test`，不要在真实环境里运行 REA 的安装和连接。
