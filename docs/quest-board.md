# 委托板：不连续的剧情，自己找任务

> 2026-10-18。用户原则：**剧情不一定是连续的，可以像 RPG 那样自己去接任务、找任务。**
> 这条和 `docs/knowledge-depth.md` 是一对：知识点要在不同剧情里以不同深度复现，而**剧情之间不必有先后**——
> 玩家自己决定先接哪一份。

## 1. 顺序自由带来的三条硬约束

1. **每份委托必须自己站得住。** 不能假设玩家做过上一关，否则「自由接任务」就变成「自由卡关」。
   委托里用到的知识点，要么它自己教到，要么在接取时用一个三十秒的前情补上。
2. **前置条件不能用等级。** 用两种：
   - `after`：必须先做过某件事（某份委托、某个动作）；
   - `knows`（`needs`）：某个知识点至少到过哪一层（L1–L4，见知识点文档）。
3. **任务要能被「找到」。** 不是自动弹出来，而是有来源：委托板、NPC 聊天、传闻、看到的某样东西。

## 2. 循环

```
找到来源 → 出现在委托板 → 接取 → 在镇上/房间里做完 → 结案评星 → 知识点等级 +1
                                          ↘ 复勘（同一份，撤掉帮助、换对抗样本）
```

**两层委托**（`prologue-quests.js` 的 `tier`）：

- **core · 六份基础委托**：只讲 REA 最基础的动作，每份一个主点，到 L2 为止，不追求「换样本再做一遍」。
- **side · 小支线**：短、可选、自己找，承担深度与迁移（L3/L4）。同一个小支线也可以复勘。

- **板上只显示接得到的任务**，锁住的写清缺什么（"先完成小林的小账本" / "数据流向要到 L2"）。
- **推荐顺序不是剧情顺序，而是「刚好高一层」**：一次跨两级的目标排在后面（脚手架理论：跳太远等于没教）。
- **可复勘的委托单独列**，玩家想刷深度自己挑。

## 3. 和知识点矩阵的关系

顺序自由后，矩阵的验收标准要加一条：

> 同一个知识点在两份不同委托里到过 L3，**并且玩家可以任意顺序遇到这两份**。

所以每份委托的 `knowledge` 标注不是"它顺带教了什么"，而是"它自己把哪个点推到了哪一层"。
如果一份委托的 L3 依赖另一份委托教过的内容，就必须写成 `after` 或 `needs`，把隐式依赖显式化。

## 4. 数据格式

```json
{
  "id": "packed-echo",
  "title": "读不动的程序：加密猫的壳",
  "giver": "老秦",
  "discover": "npc:老秦",
  "after": [],
  "needs": ["static-read:L2"],
  "knowledge": [{ "id": "packing", "depth": "L3" }, { "id": "epistemics", "depth": "L3" }],
  "repeatable": false,
  "replayOf": null
}
```

| 字段 | 含义 |
|---|---|
| `discover` | `board`（一开始就贴在本子上） / `npc:某某` / `rumor:关键词` / `object:某物` |
| `after` | 必须先完成的委托 id |
| `needs` | `"知识点:层"`，如 `"data-flow:L2"`；只写知识点时默认 L1 |
| `knowledge` | 这份委托能把哪些点推到哪一层（给推荐排序用） |
| `repeatable` / `replayOf` | 复勘：可以重做；`replayOf` 指向它复勘的那一份 |

## 5. 代码

`public/quest-board.js`（纯函数，无 DOM）：

| 函数 | 作用 |
|---|---|
| `questState(quest, player)` | `done` / `undiscovered` / `locked` / `available`，附原因 |
| `availableQuests(quests, player)` | 板上能接的，按"刚好高一层"排序 |
| `recommendQuests(quests, player, n)` | 推荐接下来的 n 个 |
| `knowledgeGain(quest, player)` | 这份委托能推多少层、推哪些点 |
| `replayableQuests(quests, player)` | 可以复勘的 |
| `parseNeed` / `sourceSeen` / `levelRank` | 前置条件与来源判定的小工具 |

## 8. 验收

- 玩家在开局就能看到 2–3 份可接委托，且**任意顺序**做完都不卡。
- 锁住的委托必须说清楚缺什么（做完哪份 / 哪个知识点到哪层）。
- 每个知识点至少有两份委托把它推到 L3，且这两份的先后可以互换。
