# 同一知识点，多层剧情

> 2026-10-18。用户原则：**同一知识点的深浅可以塞进不同的剧情里，不一定挤在同一个游戏（同一段主线）里。**
> 这条原则解决了序章的定位问题：序章不需要「完全讲透 REA」，它只需要把每个知识点教到一个**地板深度**，
> 并在后面不同的故事里换载体复现、加深。

## 1. 深度四级

| 层 | 名称 | 玩家能做到 | 怎么证明 |
|---|---|---|---|
| **L1** | 见过 | 认得出这个词，知道它属于哪类问题 | 在对话里被提到、在场景里出现过 |
| **L2** | 说得出 | 能用自己的话解释，并指出它在这个软件里的位置 | 推理板拼对、结案能复述 |
| **L3** | 做得出 | 换一个**没见过的样本**，独立做一遍 | 另一个故事的同一动作 |
| **L4** | 判得准 | 知道它什么时候失效、该换什么手段 | 对抗样本（加壳、反调试）或不给结论也算对 |

**关键结论：L3 不能靠同一个故事刷第二遍。** 同一个样本再做一次是记忆，不是迁移。

## 2. 两条硬规则

1. **一个 L3 必须在至少两个不同故事里出现**（不同委托人、不同样本、不同失败模式）。
   只有一次，玩家只是「跟着走过一遍」。
2. **深度靠撤脚手架递进，不靠加内容**（见 `docs/teaching-game-balance.md` 第 4 节）：
   同一个动作，第一次有人带、有提示；第二次撤提示；第三次换对抗样本。

## 3. 现状：每个知识点只教了一次

`node scripts/knowledge-matrix.mjs` 的输出（2026-10-18）：

```
知识点共 12 个，出现在 2 个以上故事的：4 个
到过 L3（做得出）的：9 个
在两个以上故事里到过 L3 的：0 个   ← 问题在这里
```

也就是说：**数据流向、硬编码密钥、存档格式、加壳、证据与结论……每一个都只在一个故事里到过 L3。**
玩家玩完六个委托，等于「每样都跟着做过一次」，没有一样在陌生样本上独立做过。

这正好印证了用户的原则：不是知识点不够，是**同一个知识点没有在不同剧情里复现**。

## 4. 分配建议（REA 原理与局限）

| 知识点 | 序章（现在的六关） | 后面放哪（换载体） |
|---|---|---|
| 静态读代码 | L2（小林 / 加密猫） | 时代关卡的档案检索：L3 |
| 数据流向 | L3（小林） | 天气助手改成「数据流向」二刷：L3，换一个人教 |
| 硬编码密钥 | L3（阿哲） | 工具铺的发布检查：L3，玩家帮铁叔查自己的程序 |
| 权限与声明 | L3（王奶奶） | 镇上的小卖部小程序：L3，同一个动作换个行业 |
| 存档格式 | L3（朵朵） | 图书馆的旧档案：L3，格式换成二进制而不是 JSON |
| 编码 ≠ 加密 | L3（朵朵） | 终章的「加密承诺」：L4（看着像加密，其实只是编码） |
| 本地检查不可靠 | L2（小雨） | 复勘：L3，换个软件做同样的绕过 |
| 隐藏入口 | L3（小雨） | 时代关卡的开发者模式：L2 补充 |
| 版本对比 | L2（周姐，还没做成关卡） | 做成关卡后 L3；复勘里加入「悄悄删掉的功能」 |
| 运行时验证 | L3（小林抓包） | 加密猫的下一步（hook / tcpdump）：L3；动态站：L4 |
| 加壳与混淆 | L3（加密猫） | 复勘对抗档：L4 |
| 证据与结论 | L3（加密猫） | 终章对质：L4（证据够不够，决定敢不敢下结论） |

## 5. 对序章定位的影响

原来那份毕业标准（`docs/prologue-principles.md`）要收一下：

- **序章只承诺 L2 的地板 + 每个知识点一次 L3 的体验**，不承诺「完全了解原理和局限」。
- 「完全了解」由**多个载体共同完成**：序章（L2-L3）→ 时代关卡（L3）→ 复勘（L3-L4）→ 专家档（L4）→ 系列后面几部（换学科、换载体）。
- 「能自己去逆向」的判定点只有一个：**专家档用陌生软件做出五问**。它不属于序章，属于毕业。

## 6. 数据与工具

- 知识点目录与每份委托的深度标注在 **`public/prologue-quests.js`**（`KNOWLEDGE_POINTS` + `PROLOGUE_QUESTS`）。
- `node scripts/knowledge-matrix.mjs` 直接读这份清单，输出矩阵与缺口（`coverageGaps()` 也会列出只在一次里到过 L3 的点）。
- 案例 JSON 里如果写了 `knowledge`，优先于委托清单（现在 `packed-echo` 两边一致）。

## 7. 验收

**六份基础委托只承诺 L2 的地板**（每份一个主点，做到「说得出、做一遍」），深度由小支线承担：

1. 每个基础委托的主点，在结案复盘里能用一句话说清，并指到具体那一行。
2. 每个知识点至少要有**两份小支线**把它推到 L3（不同委托人、不同样本、不同失败模式）；写不出两份，就先别加这个点。
3. 每个 L3 动作，第二次出现时**撤掉提示**并**换样本**。
4. 两次出现必须能**任意顺序**遇到（剧情不连续，见 `docs/quest-board.md`）：有隐式依赖就写成 `after` / `needs`。
5. 校验方式：`node scripts/knowledge-matrix.mjs` 的「只在 1 个故事里出现」清单，就是待补的支线清单。
