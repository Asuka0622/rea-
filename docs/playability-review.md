# 可玩性拆解：序章这套玩法核心在哪、缺什么

更新：2026-10-17。分析对象：比特镇第一部序章（REA 侦探委托）当前可玩的五关 + 复勘框架。
方法：MDA（机制-动态-体验）+ 心流。结论先行，每条给判断和依据。

## 1. 核心玩法原子拆解

- **核心动词：比对**。把「软件实际在做什么」（代码行、运行结果）和「需要被解释的句子空格」对上。
  玩家 80% 的有效思考都在做这件事：小词典给中文→代码词，终端搜出代码行，行里的名字拖进推理句。
- **基础规则（5 条）**：
  1. 房间里可调查的东西给「中文概念 → 代码词」的映射；
  2. 终端搜代码词，搜到的行可以「记名字」「钉为证据」；
  3. 推理句的空格只能用记下来的名字填，一组全对才盖章；
  4. 沙盒里亲手触发一次，结果成为证据；
  5. 对质时用证据戳穿说法，假话全戳穿即结案。
- **涌现复杂度**：来自一词多义（一个中文概念对应多个代码词）、搜索结果跨文件跳转、证据与说法一对多。
  **实际很浅**：空格数量固定、答案唯一、小词典几乎直给。
- **张力结构**：短期「下一处搜什么」→ 弱（无失败、无资源、无时限）；长期「技能点亮 + 复勘星级」→ 未成内容。
  **整条链几乎没有「会输」的可能**，这是所有问题的总根。
- **经典对标**：最像《Case of the Golden Idol》的填词推理，但 Golden Idol 靠「信息不透明 + 场景重演 + 一次机会」造张力；我们靠「问号 + 目标条」把信息全部透明化。
  次要对标：《Papers, Please》的「核对 + 盖章」——它有罚款和家庭压力，我们只有盖章。

## 2. 核心乐趣诊断

一句话：**「看懂一个软件在偷偷干什么」的智力满足**。这个乐趣是真的，而且有教育价值；
但它被六步流程稀释成「跟着问号走完全程」，玩家记住的是流程不是洞察。

## 3. 可玩性评估

| 维度 | 判断 | 依据 |
|---|---|---|
| 上手门槛 | 低，且低到没有学习曲线 | 第一关教会流程，之后零新信息；目标条逐步预告，玩家不需要判断 |
| 操作爽感与反馈 | 中偏弱 | 走路、盖章、线索音效有反馈；但核心动作「填词」没有手感，拖卡片只是搬运 |
| 决策深度 | 浅 | 答案唯一、提示直给、无错误代价；三关打完学到的是「跟着走」不是「怎么查」 |
| 重复可玩性 | 靠三档难度 + 复勘，但目前是量的变化 | 复勘只是「去提示 + 加干扰词」，机制没变 |
| 目标循环完整性 | 中循环完整，长循环断裂 | 单案 15–30 分钟完整；但六案是同一套动作重播，第 N 案不因前 N-1 案而不同 |

心流位置：难度长期贴在「玩家技能线」下方——不焦虑，但也从来不进入「挑战区」。

## 4. 最可能让人流失或无聊的点（按危险排序）

1. **第 15–25 分钟的「预测感」**：第二关就学会模式，之后每关都是已知流程重播。
  这正是「怎么都是搜集线索」的来源——它不是某一关的问题，是六关共用一套骨架的问题。
2. **问号 + 目标条把探索变成了待办清单**：侦探的乐趣是自己决定看什么；现在是游戏说「找下一条线索」。
   agency（主动权）被拿掉，玩家从「调查者」降级成「执行员」。
3. **填词没有「我真的推理出来了」的时刻**：只有「我找到了该填的词」。
4. **走路是纯开销**：320×180 房间 + 自动寻路，自动化实测每件调查物平均等 1.5–2.5 秒，
   一关 6 件就是十几秒在看小人蹭地板，且这十几秒没有任何信息。
5. **终端搜索是查字典不是读代码**：中文→代码词一一对应，玩家从不真正理解那行代码在干什么。
6. **没有失败**：没有紧张，也没有「差一点」的记忆。结案三星和全程无错没有区别。
7. **六关共用同一套 UI 语言**（手账、终端、对质、进度条），视觉上无法区分「我进行到哪、这一案和上一案有什么不同」。

## 5. 优化建议（分优先级）

### 高（立刻改，改的是结构不是内容）
1. **目标条从「指引」改成「委托人的请求」**：只说目标，不列待办；问号改成「玩家盯着某物超过 3 秒才浮现」，
   或者只在第一二关出现。这一条直接修 agency，成本最低。
2. **每关换一个核心壳**（`docs/case-mechanics.md` 第 9 节已规划）：第一关保留现流程当教学，
   第二关起必须换手上动作——搜集线索降级为配菜，主菜换成审读台 / 排除网格 / 时间线 / 连线等。
3. **走路开销砍掉**：视野内的调查物「点击即交互，不走过去」；只有需要看全景时才走。
   实测可省掉每关 10 秒以上的无效等待。

### 中（增强体验）
4. **填词改造成「归类 + 排除」**：给 8 个词 4 个槽，混 2 个干扰词，填错给「差一点」的反馈而不是静默允许。
5. **允许失败**：沙盒实验可以「改坏」，代价是星级和时间，不是卡关；对质错一次要有 visible cost。
6. **每案一个独有小规则**：朵朵关改存档有次数上限、小雨关序列 3 次清空、阿哲关扫描有冷却——
   同一骨架下制造「这一案不一样」的记忆点。

### 低（锦上添花）
7. **每关一个主色 + 一个专属 UI 元素**（阿哲的扫描仪、王奶奶的老花镜、小雨的计算器键盘），
   让进度在视觉上可感知。
8. **长循环让能力复用**：第 N 案要求用前 N-1 案学会的方法（例：王奶奶关里要用第 2 关的密钥自查思路查权限）。

## 6. 具体落地示例

- **目标条改写法**：现在「当前目标：调查现场 · 线索 3/5 ▸ 找下一条线索」；
  改成「王奶奶：它一装就问我要通讯录，还要知道我在哪儿……」——只保留委托人的原话，
  进度收进手账页眉（`线索 3/5` 小字），不再当导航。
- **填词改写法**：`board` 数据加 `decoys: ["entries", "whenReady"]`，手账多渲染两张干扰卡；
  盖错章时 `sayEl` 显示「有一个词放错了，但句子读起来很通」——制造 Golden Idol 式的「差一点」。
- **走路改写法**：`navigateCaseThing` 里若目标在视野内（屏幕 320×180 内）直接 `inspect`，
  否则才 `walkTo`。约 20 行改动。

## 7. 参考案例

- **《Case of the Golden Idol》**：同样是填词推理，但每一章的推理机制都不同（填空 → 排序 → 配对 → 排除），
  且现场信息不透明、有死亡场景重演。它证明「填词」本身不过时，过时的是「每章都一样」。
- **《Papers, Please》**：核心动作只有「核对 + 盖章」，却靠罚款、家庭支出来自每天的压力，
  同一个动作玩 20 天不腻。它证明「动作少」不可怕，可怕的是「动作少且没有代价」。

## 8. 一句话总结

**机制层不缺东西，缺的是张力和差异**：把「会输的可能」和「每关不一样的手上动作」补上，
这套玩法才从「能通关的教学流程」变成「想再玩一次的游戏」。
