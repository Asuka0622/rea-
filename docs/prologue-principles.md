# 序章要做到什么程度：毕业标准与原理/局限关卡

> 2026-10-18。用户目标：**通过序章后，完全了解 REA 的原理和局限性，之后能自己去逆向想研究的软件。**
> 本文回答三件事：现在差多远、毕业怎么判定、要补哪几块。落地细节仍以 `docs/gameplay.md`、`docs/case-mechanics.md`、`docs/teaching-game-balance.md` 为准。

## 1. 现在的六个委托教到哪

六个委托教的是**风险点**（隐私、权限、密钥、后门、版本、本地校验），不是**手段**。
玩家学会「这个 App 有问题」，但没学会「我是用哪种手段看出来的、这种手段什么时候不管用」。

| 关 | 现在的壳子 | 实际教到 | 离「原理」缺什么 |
|---|---|---|---|
| 小林 | 审读台 | 隐私条款 vs 行为 | 没讲「数据流怎么从代码里读出来」 |
| 阿哲 | 排除网格 | 硬编码密钥 | 没讲「为什么客户端里藏不住」 |
| 小雨 | 输入序列 | 彩蛋 / 后门 | 没讲「入口是怎么被找到的」 |
| 朵朵 | 存档编辑 | 编码 ≠ 加密、校验和 | 没讲「格式是怎么还原的」 |
| 王奶奶 | 数据流连线 | 最小权限 | 没讲「清单只是声明，行为要动态看」 |
| 周姐 | 双栏对比 | 版本 diff | 没讲「看不到的改动怎么办」 |

一句话：**六个壳子都是从业者的真实动作，但都停在应用层静态分析，而且没有一次「工具失败」的体验。**

## 2. 毕业标准（可检验）

序章通过 = 三件事同时成立。

### A. 能说清 5 条原理

1. 程序是「数据 + 指令」；静态分析看文件，动态分析看运行，两者缺一不可。
2. 反编译 / 反汇编给的是**近似**结果：名字、类型、注释都丢了，看到的是「可能的源码」。
3. 还原行为靠三条线：**数据流**（从哪进来、经过谁、发到哪去）、**控制流**（什么时候被调用）、**符号**（字符串、导入表、配置）。
4. 验证手段只有四种：抓包、沙盒运行、改数据副本、下断点。看代码得出的只是假设。
5. 结论要能落到证据：每条判断都能指到某一行、某个请求、某次实验。

### B. 能说清 4 条局限

1. 加壳、混淆、优化会让静态分析几乎读不动。
2. 加密的通信与数据，静态看不到明文。
3. 反调试、完整性校验会阻止动态分析。
4. 工具会错、会漏；本地检查挡不住有权限的人；授权与法律边界先于技术。

### C. 完成 1 次陌生样本分析（迁移任务）

给一个没见过的软件（不带动画提示、不带角色），玩家用工作台跑一遍，回答五问：
**要了什么、数据发去哪、密钥在哪、有没有隐藏入口、能不能验证**。
这一步是「学会」的唯一证据，也是 `docs/teaching-game-balance.md` 里已经写下的「专家档」。

## 3. 要补的四块

### 3.1 原理站一：反汇编入门（native）

- **样本**：一个小的 `.so` / `.exe`（自己编译、带授权检查）。
- **壳子**：**调用图连线**——从字符串和导入表出发，连出「谁调用了检查函数」。
- **手上的动作**：找字符串 → 看引用 → 顺着交叉引用找到比较指令 → 画出调用链。
- **教的原理**：第 2 条（近似）、第 3 条（三条线）。
- **给的局限**：优化过的代码读起来像乱码；没有符号名，只能靠常量猜。

### 3.2 原理站二：动态分析

- **样本**：与原理站一同一个程序，但关键值只在运行时算出来（静态看不到）。
- **壳子**：**下断点**——在沙盒里跑到某个位置停住，看变量与请求。
- **教的原理**：第 1 条（动态）、第 4 条（验证）。
- **给的局限**：加了反调试的版本跑不起来，只能回到静态。

### 3.3 失败站：一关「证据不足」

- **样本**：加壳 / 混淆过的程序，工具只吐噪音。
- **正确通关**：不是「找出后门」，而是**写出「证据不足，不能下结论」+ 待验证清单 + 下一步该换什么手段**。
- **评分**：主张越肯定、证据越少，星级越低；这一关**禁止**凭猜测盖章（推理板只接受「证据够」的组）。
- **教什么**：局限不是提示里的一句话，而是玩家亲手撞上的墙。
- **为什么值得先做**：不依赖新美术（场景可复用事务所），却是唯一能把「局限」变成体验的关卡。

### 3.4 专家档：结业实操

- 工作台从「木框里的道具」变成「毕业后的工具」：事务所二楼开一个实验室入口。
- 流程：选一个自己的软件 → 跑工作台 → 回答五问 → 系统按证据链评分。
- 复用现有：`public/app.js` 的真实分析流、报告阅读、复刻说明书。

## 4. 和现有系统的接法

| 现有系统 | 怎么用 |
|---|---|
| 行动点 / 心证（`public/case-tension.js`） | 原理站天然适用：静态手段有限，每看一处都花点；「证据不足」也可以是一种失败（乱下结论扣心证） |
| 复勘（drill） | 对抗变体放这里：加壳版、反调试版、混淆版 |
| 技能树主干六 | 增加「手段」子线：静态 / 动态 / native / 对抗，每关点亮 |
| 推理板 | 失败站需要新增一个「证据阈值」：证据不足时不允许盖章 |
| 结案复盘 | 每关复盘里固定回答「这次用了哪种手段、它哪里不灵」 |

## 5. 落地顺序（建议）

1. **失败站**（最低成本、最高收益）：学会「不能下结论」，同时把推理板的「证据阈值」做出来，后面两站都要用。
2. **动态分析站**：复用 `case-labs.js` 现有的 network / calculator / save 三套沙盒，加「断点」壳子。
3. **反汇编站**：需要真样本和调用图界面，工程量最大。
4. **专家档**：依赖工作台评分口径，最后做。

## 6. 验收

- 每站都有：一个真实样本、一套可判定的得分、一次「局限」体验。
- 毕业判定写进技能树状态：6 个委托 + 2 个原理站 + 失败站 + 专家档成绩，缺一不算毕业。
- 教学侧验收：找 3 个人做一次陌生样本分析，能有 2 个人独立写出「五问」答案。

## 7. 还没定

- 「完全了解原理」要不要包含**脱壳**与**协议还原**？这两块已经在专家档的边界外，可能留给第二部。
- 失败站的「证据阈值」定多严：太严会劝退，太松就变成猜谜。

## 8. 进度（2026-10-18）

失败站已经从设计变成可玩的第一版：

| 东西 | 状态 | 位置 |
|---|---|---|
| 证据阈值（推理盖章前必须够证据） | ✅ | `public/case-tension.js` 的 `canStamp`，两个引擎都接上 |
| 无对质的委托（实验做完即结案） | ✅ | `case-puzzle.js` / `case-session.js` / `case-progress.js` |
| 故意失败的实验（沙盒跑不起来） | ✅ | `case-labs.js` 的 `packed` 分支 |
| 失败站案例「读不动的程序：加密猫的壳」 | ✅ 案例馆可玩 | `samples/cases/packed-echo/` |
| 镇上第 7 个委托（房间、NPC、任务条目） | ⬜ 未接 | 需要 client home 与房间美术 |

案例的四条推理正好对应「能确定 → 能看见 → 只能运行时验证 → 证据不足」，`need` 依次是 0/1/2/3：
**连「证据不足」这句话都要先攒够三件证据才能盖章**，这是这一关最核心的教学动作。

验证：`case-puzzle` / `case-library` / `case-tension` 三套用例覆盖了词条可达、房间站位、美术存在、阈值判定与存档往返；全量回归 127 项通过。
