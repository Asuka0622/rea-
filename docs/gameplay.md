# 玩法研究：怎么让「学计算机」本身就好玩

> 2026-10-15，小克整理，供讨论。总设计见 `docs/concept.md`。

## 1. 现在的问题

现在的玩法基本是「走路 → 对话 → 答题」。小游戏包装得再好，本质还是分类题、填空题，玩久了像练习册。

教育游戏研究里有个说法：**「巧克力包西兰花」**——游戏是外壳，题目是硬塞进去的，两者分开，玩家很快就会觉得「这是在考试」。研究里更有效的做法叫**内在整合**（intrinsic integration，Habgood 与 Ainsworth 2011 年的研究）：**玩法的规则本身就是要学的知识**，玩得越好，懂得越深。

## 2. 参考：把「学」做得好玩的游戏

| 类型 | 代表作 | 好在哪 | 我们能借什么 |
|---|---|---|---|
| 指令编排 | 《程序员升职记》（Human Resource Machine）、Lightbot | 用很少的指令卡让小人搬箱子，不知不觉学会了汇编、循环、跳转 | 打孔卡、钟楼指令、比比的行动程序 |
| 从零造电脑 | 《图灵完备》（Turing Complete） | 从一个与非门开始，一路搭出加法器、内存、CPU，每一关都是上一关的零件 | 1940 年代：亲手搭逻辑门和加法器 |
| 开放式解谜 + 成绩对比 | 《Opus Magnum》等 Zachtronics 游戏 | 一道题有很多种解法，通关后显示「你用了多少步、多少零件」，和别人的分布对比，让人想再优化 | **算法的快慢不用讲，玩家自己会想把步数降下来** |
| 流水线与物流 | 《异形工厂》（shapez）、《Mini Metro》 | 设计传送带和线路，吞吐量、堵塞、并行一眼就看得见 | 活字排版的两块铁板（流水线）、数据包路由、驿站分拣 |
| 推理与证据 | 《逆转裁判》、《奥伯拉丁的回归》 | 收集证据、出示证据、推出真相 | 已经用在侦探支线；安全、逆向、AI 核实 |
| 搜索数据库 | 《Her Story》 | 玩家自己输入关键词，在一大堆录像片段里搜，拼出真相 | **数据库和搜索**：在档案馆里自己写查询找线索 |
| 规则核对 | 《请出示文件》（Papers, Please） | 按越来越复杂的规则检查证件，放行或拒绝 | 中世纪城门：口令、印章、签名验证（身份验证、数字签名） |
| 嵌在故事里的谜题 | 《雷顿教授》 | 每个谜题都是剧情里某个人遇到的难题，解完有评分和收集 | 每个知识点都是某位角色遇到的麻烦 |
| 温馨日常 | 《星露谷物语》 | 每天有事做，和镇民建立关系，四季变化，慢慢把家布置起来 | 比特镇的日常、师傅的好感度、收藏和装饰 |
| 终端与黑客 | 《Hacknet》 | 真的输入命令行，像在用一台真电脑 | 硬核难度：在比特镇用真实的命令和代码 |

## 3. 我们的玩法支柱

1. **动手解谜（核心）**：每个知识点配一种机关，**机关的规则就是知识本身**。尽量做成**有多种解法**的开放题，通关后给评分（完成、步数、零件数），玩家会自己想优化，「快慢」「复杂度」不用讲就懂了。
2. **探索与推理**：在时代地图里找人、找线索；用推理、出示证据、搜索档案的方式推进剧情。
3. **比特镇的日常**：师傅的好感度（越熟越肯教你深的东西）、每日委托、复习信、四季、收藏各时代的纪念品来布置事务所。
4. **成长与收集**：技能树、成就、知识卡图鉴、每道谜题的星级、路米的时代装。

## 4. 机关类型清单（同一个时代不重复用同一种）

| 机关 | 玩法 | 教什么 |
|---|---|---|
| **指令卡编程** | 把指令卡排成一列，按「运行」看机器一步步执行；可以有循环卡、条件卡、跳转卡 | 顺序、循环、条件、函数、调试 |
| **搭电路** | 拖线连接开关、灯和逻辑门，点亮目标灯 | 逻辑门、二进制加法、时钟 |
| **流水线** | 摆放工位和传送带，让东西源源不断地产出；有吞吐量统计 | 流水线、并行、瓶颈 |
| **线路网络** | 在地图上连线路，让信件或数据包从 A 送到 B，有的线路会断 | 路由、冗余、TCP 重传 |
| **节奏与信号** | 跟着节拍发信号（烽火、摩尔斯电码），或者听信号解码 | 编码、时钟信号、协议 |
| **密码与破译** | 转动密码盘、统计字母出现的次数、试钥匙 | 加密、频率分析、暴力破解为什么慢 |
| **规则核对** | 一个个检查来人，按规则放行或拒绝，规则越来越多 | 身份验证、权限、签名 |
| **搜索档案** | 自己输入关键词或拼出查询条件，在档案里找线索 | 搜索、索引、数据库查询 |
| **调参实验** | 拖动几个参数，看曲线或机器的反应，找到合适的值 | 反馈控制、AI 训练、偏差 |
| **推理与出示证据** | 收集证据，在对质时出示 | 安全分析、逆向、核实 AI 的回答 |
| **小剧场经营** | 短时间内处理一串客人或任务（像《胡闹厨房》的简化版） | 队列、并发、调度 |

## 5. 每个时代测试段的玩法草案（每段 2 个，不重复）

| 时代 | 第一段 | 第二段 |
|---|---|---|
| 比特镇序章 | 二进制灯（节奏和规律）、零件归类 | 两个抽屉 |
| 古代中国 | **茶铺算账**：客人排队结账，在桌上摆算筹，又快又准（小剧场经营 + 位值制） | **调天衡**：拖动配重和水流，看节拍曲线变匀（调参实验 + 时钟信号） |
| 中世纪欧洲 | **城门守卫**：检查口令和印章，放行或拒绝（规则核对 + 身份验证） | **破译密信**：转动凯撒密码盘，硬核难度用字母频率分析（密码与破译） |
| 工业革命 | **打孔卡织布**：在卡片上打孔，看织布机织出图案；用「重复」卡省掉一大摞卡片（指令卡编程 + 循环） | **电报员**：跟着节拍发摩尔斯电码（节奏与信号 + 编码） |
| 1940 年代 | **搭加法器**：用开关和逻辑门搭出能加法的电路（搭电路） | **破译机**：设计自动试钥匙的顺序，比一比手工要试多久（算法的快慢） |
| 1960–90 年代 | **连接两所大学**：连线路，让数据包绕过断线送到（线路网络 + 路由） | **第一个网页**：用标签积木搭出网页（指令卡编程的变体） |
| 现代都市 | **训练比比**：挑训练资料，看比比学歪还是学对（调参实验 + 数据偏见） | **核实比比的回答**：在档案里搜索证据，证明它哪里说错了（搜索档案 + 推理） |

每段解完都有评分：轻松看「完成」；标准加上「步数」；硬核再加上「零件数」和挑战条件。

## 6. 已定（2026-10-15）

1. **整体手感：A，温馨 RPG + 谜题关卡**（像《星露谷物语》加《雷顿教授》）。在世界里走、和人聊，谜题嵌在剧情里，每道谜题是某位角色遇到的麻烦。
2. **硬核难度试着加入真正写代码**：先在比特镇的「回来对照」环节试做（比如用几行 JavaScript 做一遍刚在时代里用机关做过的事），效果好再推广。
3. **评分和别人比：暂定**。先只显示自己的成绩（完成、步数、零件数）；以后再决定和「镇民平均」比，还是联网比。

## 7. 当初讨论的问题（留档）

1. **整体手感偏向哪种？**
   - A. **温馨 RPG + 谜题关卡**（像《星露谷》加《雷顿教授》）：在世界里走、和人聊，谜题嵌在剧情里。**推荐**，和现在的方向最接近。
   - B. **谜题为主**（像 Zachtronics 系列）：每个时代就是一组越来越难的机关关卡，剧情是串场。
   - C. **冒险推理为主**（像《逆转裁判》）：以查案、推理推动，机关是辅助。
2. **硬核难度要不要真的写代码**（在比特镇用真实的 JavaScript 或命令行）？
3. **开放式解谜的评分要不要做「和其他玩家比」**（需要联网），还是只和「镇民平均」比（本地虚构数据）？
